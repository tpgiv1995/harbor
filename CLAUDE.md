# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Harbor**; a Windows desktop app for running and monitoring multiple Claude Code sessions at once. Since the **"Slate" redesign (2026-07-18, Claude-design handoff)** the main surface is NOT a terminal: a session rail opens sessions as **designed conversation windows** (prompt bubbles → assistant prose → tool-action rows, parsed live from the session's `~/.claude/projects` JSONL transcript) on an adaptive free-form stage (up to **16** open windows: 1 full, 2 split, then an equal-cell grid 2×2 → 3×2 → 3×3 → 4×3 → 4×4, drag a window header to rearrange), driven by one **universal command bar** at the bottom. The command bar's model chip opens a per-session **capability menu** (live models, effort, permission mode, honest fast mode, plugins, live slash commands). A per-window `>_` toggle flips to the real xterm.js terminal (permission prompts live in the pty, not the transcript). It is an **Electron GUI head on Harbor's own session daemon, sessiond**: `app/src/daemon/` is the daemon (one keeper process per session holding the pty; ConPTY on Windows), `app/src/main/session-daemon/` is the app-side control client and stream supervisor, and `session-daemon/factory.js` is the only door to the backend. **The Herdr backend was retired 2026-08-14**: `app/src/main/herdr/` is deleted and `HARBOR_SESSION_BACKEND=herdr` throws `HARBOR_SESSION_BACKEND=herdr is no longer supported because the Herdr backend was retired; use sessiond`. Pane control goes through the sessiond supervisor via `session-daemon/factory.js`, while conversations render from transcripts.

Slate design tokens are reproduced in `app/src/renderer/styles.css` (the original `design_handoff_harbor_slate/` download was Linux-era). The pre-Slate design record is `docs/ARCHITECTURE-v2.md`, historical for the daemon plumbing and superseded by `docs/SESSION-DAEMON-CUTOVER.md`, the real record of the sessiond cutover. Requirements: `docs/REQUIREMENTS-v2.md`. Build narrative: `docs/SETUP-LOG.md`. The Linux/Herdr-era CLAUDE.md narrative (wedge recovery, protocol allowlist, systemd unit doctrine, xvfb/dbus gate, X11 focus guard, keyd) is preserved in `docs/CLAUDE-md-archive-linux-era.md`; the principles those incidents taught are carried forward in the bullets below and in `docs/claude/`.

## Machine and shared state

- Harbor runs on Pat's Lenovo Legion, Windows 11. The old Linux install was retired 2026-08-10; anything dated before that describes the old machine.
- **Shared app state lives at `~/.harbor` on win32, deliberately OUTSIDE `%APPDATA%`** (2026-08-13): Claude Code runs in an MSIX container whose `%APPDATA%` is a per-launcher VIRTUALIZED mirror, so a "fix" written there never reaches the real app; profile order was "fixed" in the mirror five separate times while the real app rendered the stale real file, and 52 of 64 project icons existed only in the mirror. The user-profile ROOT is not virtualized, so `~/.harbor` is one file for every reader, whoever launched it. `app/src/shared/tasks-file.cjs` `sharedDataDir`/`defaultConfigFile` own the rule (`~/.harbor/config.json` on win32); a relocated userData keeps its own file, the same rule `resolveUnitPolicy` states.
- Transcripts live at `~/.claude/projects`, shared across the three config homes by junctions, which is how several accounts share one history.
- Probe the daemon read-only with `ELECTRON_RUN_AS_NODE=1 electron bin/harbor-sessiond status` (the bin script is plain Node; under Electron the env var keeps it, the daemon, and every keeper running as plain Node, see the daemon-start bullet in `docs/claude/sessiond.md`).
- `parity-check.ps1` in `~/.claude/hooks` is the profile drift guard for the two hand-synced config homes.

## Commands

All app commands run from `C:\dev\harbor\app\` (system Node, engines >=22; CI runs Node 24):

```
npm install
npm start            # launch the app (electron .); main is src/main/index.js, it does NOT need a prior build for main-process code, but the renderer must be built (npm run build) unless using dev
npm run dev          # vite dev server (127.0.0.1:5173) + electron with VITE_DEV_SERVER_URL
npm run build        # vite build -> app/dist/ (renderer only)
npm test             # node scripts/test.js: Node built-in --test over every test/**/*.test.js
npm test -- main     # filter test files by path substring
npm test -- --exclude daemon --exclude bin   # repeatable --exclude removes suites by path segment (this pair is the CI gate)
```

- **`npm run test:e2e` currently runs on NO machine.** It is the two-consecutive-runs Playwright gate built on a Linux xvfb/dbus harness (see the archive doc), and it is being ported to an offscreen-window Windows harness; until that port lands it must not be cited as coverage for anything. The unit suite is the gate that actually runs. The same applies to `test:e2e:sessiond` and the Linux-era verification family under `app/scripts/` (`verify-*`, `live-drive*`, `terminal-harness.js`): xvfb- or herdr-bound, running nowhere, owned by the same port.
- Vite `base: './'` in `vite.config.js` is required; Electron loads `dist/index.html` over `file://`, where absolute asset paths break.

## CI

`.github/workflows/ci.yml` runs the unit suite on **windows-latest**, because Windows is the platform Harbor actually runs on (the Legion is the de-facto gate machine). Flipped from ubuntu-latest on 2026-08-14 after the 49 Windows-only unit failures were cleared and the gate ran green twice consecutively on the real machine. Facts the file itself documents and this doc repeats so nobody "simplifies" them away:

- Exclusions are `--exclude daemon --exclude bin` ONLY (no herdr anywhere; that suite is deleted). `daemon` and `bin` are real-pty/polyglot harness families whose Windows ports are tracked separately; they run locally on the gate machine, and excluding them keeps CI honest about what it proves rather than red about what it cannot yet run.
- `core.autocrlf` is forced off before checkout: several specs assert byte-exact fixtures, and the Windows image's default conversion would rewrite them.
- `npm ci`, not `npm install`: the lockfile is committed, so an exact install is both possible and right.
- Reproduce the exact gate locally with `cd app && npm test -- --exclude daemon --exclude bin`.

## Architecture

Three-process Electron layout under `app/src/`:

- **`main/`**; Node/Electron main process.
  - `index.js` wires all IPC handlers and the daemon connect flow (the composition root where the isolation policies are resolved).
  - `session-daemon/`; the app-side sessiond plane, reached ONLY through `factory.js` (`resolveSessionBackend` returns `'sessiond'` or throws; the herdr value throws the retirement error, and factory also enforces the session-store policy). `client.js` is the control client over the daemon's socket (a named pipe on win32), `streams.js` the stream supervisor (exclusive control: acquire on focus, release on blur; `ensureDialogSize` lives here now), `process-tree.js` the process inspection helper.
  - `providers/`; `history.js` runs the Node `history-index.js` worker (+ fs-watch on `~/.claude/projects`), `titles.js` runs the Node Haiku titler, `artifacts.js` discovers agent-produced files for the Files view, `provider-history.js` scans the codex (`~/.codex/sessions`) and cursor (`~/.cursor/projects/*/agent-transcripts`) stores into rail rows of the same shape (title from the first user block the REAL TranscriptParser yields; cursor cwd un-munged from known cwds, honestly null when unmatched), `delegate.js` watches the claude-delegate queue, `usage.js` reuses the statusline method per account, `accounts.js` reads account emails, `capabilities.js` enumerates models/plugins/slash commands and owns the **new-session provider registry** (`newSessionOptions()`), `model-catalog.js` keeps the Claude model list current by scanning the INSTALLED CLI binary (see `docs/claude/providers.md`), `icon-gen.js` generates project icons on demand, and `transcript.js`/`pending-ask.js`/`workflow-runs.js` are described in their own bullets in `docs/claude/conversation.md` (transcript, pending-ask) and `docs/claude/views.md` (workflow runs).
  - `actions/launch.js` (resume/new) and `actions/orchestration.js` (kickoff + execute mutex; workers launch through the sessiond `createWorkspace({ cwd, command })` adapter) and `actions/takeover.js` (outside-session adoption). These shell out to `bin/` scripts and **never reimplement resume/index logic**.
  - `lifecycle.js`; much smaller since the retirement: `startSessionDaemon` (spawns `bin/harbor-sessiond start`) and the second-instance argv parsing (`parseSecondInstanceArgs`).
  - `daemon-watchdog.js`; pings the sessiond client every 30s and recovers on two consecutive failures (disabled under `HARBOR_E2E`/`HARBOR_NO_DAEMON_START`). A wedge mid-session is silent (established connections stay open), which is why the watchdog exists at all.
  - `resume-nudge.js`; `planResumeNudge`, the resume redelivery rule (see `docs/claude/sessiond.md`).
  - `notify.js`; OS notifications on unfocused-pane work→idle transitions. `lag-monitor.js`, `sidebar-bridge.js`, `terminal-bridge.js` connect main↔renderer.
- **`src/daemon/`**; the session daemon itself, plain Node with its own packed deps (`npm run pack:daemon-deps`, node-pty required): `daemon.js` (the store, spawn, reconcile), `keeper.js` (one process per session holding the pty), `daemon-watch.js` (the exit-capture watcher, see `docs/claude/sessiond.md`), `boot-id.js`, `harness-watch.js`, `dormancy.js`, `session-scope.js` (Linux-only containment, honestly `not linux` on this box), `paths.js` (store, socket, and the win32 named-pipe derivation), `client.js`, `log-file.js`, `ndjson.js`, `observer-writer.js`, `screen.js`.
- **`preload/index.js`**; `contextBridge` exposes `window.harbor` (typed IPC only, no `nodeIntegration`). An extra `api.e2e` surface is gated on `HARBOR_E2E=1`.
- **`renderer/`**; React 19 (Slate): `sidebar/Sidebar` (the rail), `ViewSwitch.jsx` (the Agents/Tasks/Orch/Files toggle at the TOP of the rail, above Sessions and P/T/S; Pat placed it there 2026-07-25), `stage/Stage` + `stage/SessionTile` + `stage/Conversation` + `stage/CommandBar` (the conversation windows and universal prompt bar), `stage/AskCard.jsx` + `stage/ask-sheet.cjs` (the in-window answer sheet for AskUserQuestion, permission and resume dialogs; doctrine in `docs/claude/conversation.md`), `stage/ComposeEditor.jsx` + `stage/compose-doc.cjs` (the WYSIWYG contenteditable composer and its markdown serializer), `stage/md.jsx` (markdown-lite, React elements only; never injected HTML), `ContextMenu.jsx` (the app-wide right-click menu carrying spelling suggestions), `terminal/XtermPane` (the per-window `>_` raw-terminal mode), `TitleBar` (live pill + rail-toggle + `⚙ workers` chip; usage meters live in the rail only), `NewSessionConfig.jsx` (the new-session popover), `providers.js` (provider identity registry for logos/colors), `orchestration/OrchPanel` + `orchestration/OrchProjectPicker`, `tasks/TasksView.jsx` + `tasks/TaskEditor.jsx`, `artifacts/ArtifactsView.jsx`, `HelpOverlay`, `styles.css` (the Slate token sheet). Vite bundles this.
- **`shared/`**; logic used by both the renderer and the main/test side (see twin rule below).

## Non-obvious conventions and gotchas

The bullets kept here are the cross-cutting non-negotiables. The per-area gotcha corpus (daemon, conversation, views, board, providers) moved verbatim to `docs/claude/`; see the index above.


- **Product code never spawns Python (2026-08-04).** The 2026-08-03 incident proved that timeouts, a slot cap, a wedge breaker and a canary can only bound a kernel-wedged interpreter; they cannot make it safe. `history-index.js` owns indexing, `titles.js` owns Haiku titles, and `harbor-bin.cjs` uses the same Node index for the daily `hist` picker and workspace labels. `reference/python-oracles/` is test data for byte-equivalence only. A production `python3`, `.py` spawn, or `sharedPythonRunner` reference is a release blocker. `createSessionOwnerProbe` still carries a 3s deadline on both of its process questions, because that independent incident guard remains necessary.
- **`.js` / `.cjs` twins in `src/shared/`.** Every shared module ships as both an ESM `.js` (imported by the renderer JSX) and a CommonJS `.cjs` (required by the main process and the Node test runner): `sidebar-model`, `date-roll`, `terminal-layout`, `artifact-url`, and kin. **Edit both twins together and keep them identical**; drift silently breaks either the UI or the tests. Tests import the `.cjs` variant.
- **Tests must never touch the real user daemon.** Isolate with `HARBOR_SESSIOND_DIR`/`HARBOR_SESSIOND_SOCKET`; `HARBOR_NO_DAEMON_START=1` skips clean-start. Orchestration-kickoff tests run with `CLAUDE_DELEGATE_DRY_RUN=1` against a throwaway workspace; never spawn real workers. A relocated store gets no systemd unit and no scopes unless it names its own (`resolveUnitPolicy` in `bin/harbor-bin.cjs`, the durable rule from the 2026-07-29 unit-name incident in the archive: a resource NAME is a shared namespace, and a harness pointed at a stub is by definition not the real installation, so the default name is not its name to touch). **And a harness sessiond dies WITH its harness (`src/daemon/harness-watch.js`, 2026-08-08).** Every daemon suite's teardown was correct, and none of it runs when the runner is killed: three interrupted `npm test` invocations left 28 orphaned daemons idling since the previous evening, the second pile of this exact shape (daemon.js's shutdown comment records the first, 2026-08-06). The floor is in the daemon, not in each suite: a daemon whose store is relocated defaults to watching the pid that spawned it and, when that pid dies, SIGKILLs its own store's sessions and exits. `HARBOR_SESSIOND_PARENT_PID=<pid>` names the harness explicitly, `=0` opts out, and `bin/harbor-sessiond start` sets the opt-out because a deliberate detached start MEANS to outlive its caller. The default store never watches anything. Proof is two-sided in `test/daemon/harness-reaper.test.js`: an orphaned relocated daemon must reap itself AND its session, and an opted-out one must survive its spawner.
- **A harness cannot signal or launch on the real machine: the isolation guards (`main/isolation.js`, 2026-07-25).** Socket, profile and display isolation are NOT enough, because they do not isolate `$HOME`: a config-modal drive that stubbed `window.harbor.session.send` still killed the live session running it, since Apply on a PANELESS session routes through `session.takeover` (`reconfigureSelected` -> `takeoverSelected`, never stubbed) and the takeover owner pid came from the statusline tee, whose directory was hardcoded to the real `~/.cache/harbor/context`. Session 31899b4f died mid tool call: it killed itself with its own repro. One decision now runs per instance at the composition root. `HARBOR_CONTEXT_DIR` relocates the tee store (both the takeover owner lookup and `transcript.js`), so a harness can be made unable to even learn a real pid. `resolveSignalPolicy` refuses every real signal from an instance whose `userData` is not the Electron default while it reads the REAL store; it wraps the injected `processKill` for BOTH signalling paths (the takeover kill and `closePaneTab`'s orphan escalation) plus an `assertSignalsAllowed` check at the kill itself, and signal 0 always passes because every liveness probe needs it. `resolveLaunchPolicy` refuses the `bin/claude-sessions` / `bin/ai` shell-out from a non-default profile at all (a launch needs nothing real but the binary), with `HARBOR_E2E_FAKE_LAUNCH` still recording argv for harnesses that assert on it. `resolveDialogPolicy` (the third sibling) refuses a native file dialog from any non-default `userData`, because a dialog needs nothing real except a human to answer it, and a modal dialog BLOCKS the main process while it waits for an answer no test can give; `HARBOR_E2E_FAKE_DIALOG=<path>` supplies the answer the OS would have given and is checked BEFORE the guard on purpose, which is what makes the proof two-sided (the same click must dead-end under the guard and open the popover when the answer is supplied; the Linux session-bus incident that taught this lives in the archive). The default profile is untouched: adopt-on-send, resume and worker close behave exactly as before. Escapes are explicit and per-effect: `HARBOR_ALLOW_REAL_SIGNALS=1`, `HARBOR_ALLOW_REAL_LAUNCH=1`, `HARBOR_ALLOW_REAL_DIALOGS=1`. The proof is two-sided ON PURPOSE, because a refusal alone can pass for the wrong reason (the drive never reached the kill): spec "an isolated Harbor refuses to signal a real owner" requires the SAME Enter to kill a stand-in child under `HARBOR_ALLOW_REAL_SIGNALS=1` and to leave it alive without. **Isolating the parts you thought of is not isolation.**
- **The 8.3 short-name trap: realpath the tmpdir ONCE at the boundary (`test/support/real-tmpdir.js`, 2026-08-14).** `os.tmpdir()` answers with whatever spelling `%TEMP%` carries, and on a hosted Windows runner that is an 8.3 short name (`RUNNER~1`) because the username is nine characters. Anything downstream that realpaths, watches, or serves the same location then speaks the LONG spelling, and two names for one directory read as two directories: the 2026-08-14 CI flip failed five watcher suites and three server specs exactly this way, reproduced locally with a substituted `LONGTE~1` TEMP. It must be `fs.realpathSync.native`: the JS realpath only resolves symlinks and hands an 8.3 name straight back (measured), while the native form asks the OS for the final long path. The difference is not cosmetic: libuv's Windows `fs.watch` ABORTS THE PROCESS (`Assertion failed: !_wcsnicmp(filename, dir, dirlen)`, src\win\fs-event.c) when the watched dir was opened by its short spelling. One realpath at the boundary gives every fixture the spelling the OS itself uses, so path identity is decided once, there, not per test. macOS has the same trap through `/var` -> `/private/var`.
- **Never restack or focus windows from automation on this box, period.** win32 has NO focus guard: the old X11 outcome-checker (`focus-guard.js` reading `_NET_ACTIVE_WINDOW`, archive doc) degrades to a no-op without X, so on Windows there is nothing that hands the screen back after a mistake. Pat plays OSRS fullscreen; a scripted or agent-driven restart must not show, maximize, focus, or restack Harbor's window over anything, and there is no verification step that can excuse trying. The `--no-focus-steal` flag and `parseSecondInstanceArgs`'s honoring of it still apply to every scripted relaunch.
- **The GUI wraps `bin/`, it does not duplicate it.** Resume routes through `bin/claude-sessions --resume-id`, so the live-guard (refuses sessions active in the last 90 s), account auto-detection, and workspace routing all apply in one place.
- **A LAUNCH THAT RACES A REBUILD HEALS ITSELF (2026-08-29, "cant even open harbor, just a black screen").** Vite wipes and renames dist's hashed assets, so launching while a build lands can load an index.html whose chunks are gone: the page finishes loading, React never mounts, and the window sits on the body background looking dead, forever, because the update ribbon needs a mounted renderer and render-process-gone never fires for an empty page (Pat had been REBOOTING for this; any relaunch after the build settled would have worked). `main/boot-recovery.js` owns the recovery: probe the mount after every load, retry a failed or never-mounted load on a steady cadence, retry immediately when the dist watcher announces a settled build, and disarm permanently once mounted so a healthy window is never reloaded. Proven two-sided by `scripts/drive-boot-recovery-win.js` (fails at pre-fix HEAD on exactly the heal step) and `test/main/boot-recovery.test.js`. Do not remove the steady retry floor: the dist watcher is off under `HARBOR_E2E`, and a build can finish while no watcher is armed.
- **backdrop-filter traps fixed-position descendants** (stacking context + containing block; live-caught three times). Every popover/menu (app menu excepted; its bar is unblurred) renders through a React portal to `document.body`: model quick-switch, workers menu, xterm context menu.
- **Commit by FILE, never wholesale, when sessions intermix.** Multiple sessions work this tree at once, so the working tree routinely holds several features' hunks in one file. Attribute every hunk before committing (the orchestration research records model the method: per-file, per-hunk feature maps), use `git add -p` on mixed files or name the rider hunks in the commit body, and never `git add -A` a tree you did not fully account for. Runtime droppings (`.claude/scheduled_tasks.lock`, orchestration scratch dirs) are never committed.
