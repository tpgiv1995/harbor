# Workspace-pool core

The plain-Node implementation is in `C:\dev\.orch\harbor\lane-pool-1101\app\src\shared\lane\`.
Its CLI entry is `C:\dev\.orch\harbor\lane-pool-1101\bin\harbor-lane`.
This is the stages 1 and 2 core. It does not change launchers, sessiond, orchestration, or the live checkout.

## Identity and persistence

Repository ids, lane ids, sessions and slots are separate identities. A repository owns slot-00 for integration and N ordinary slots shared by write and executable verify lanes. Inspection reads a pinned Git object without a slot. Live inspection explicitly returns the canonical path and has no reproducibility guarantee. No code executes on behalf of either inspection type.

Each lease carries boot identity, PID and creation time, lane id, monotonically increasing slot generation, and random token. Boot identity comes from Harbor's existing boot-id module with its three-state comparison and 60-second derived-boot tolerance. A process's own uptime-derived start is a bound, not its OS birth: an observed OS birth from 120,000 ms before that bound through 1,000 ms after it is live; a later birth means PID reuse, and an earlier birth is unknown. Missing PIDs or foreign boots are gone. OS-sourced creation stamps compare exactly. Only an exact match to this process's own cached self stamp bypasses the OS observation. Mutation requires the lane's token and generation. Session keys combine provider, absolute config home and session id. Resolve them before resuming; never infer a lane from its path.

State defaults to `%USERPROFILE%\.harbor\lanes\`; an absolute `HARBOR_LANES_DIR` overrides it and must remain outside the pool. The authoritative journal contains fsynced changed records with chained checksums. Above 2,000 records, a checksummed state snapshot plus last hash seeds a fresh segment. `segments.json` atomically selects it only after both new files exist. Keep the current and previous snapshot/segment generations; load only the current snapshot and tail. A corrupt current snapshot, torn tail or broken chain refuses, never silently falls back. `registry.json` is a convenience snapshot. `events.jsonl` rotates before exceeding 5 MiB and retains two old files. Durable lane/session history remains in the state snapshots; this is not retirement.

A global lock serializes short state transactions and enforces the cross-repository write cap. Repository locks cover claim and publication, never the long checkout preparation between them. Lock records are fsynced to a temporary file and atomically hard-linked into place, so a crash before publication cannot leave an empty lock. Acquisition waits at most 60 seconds, overridden by `HARBOR_LANES_LOCK_WAIT_MS`, using bounded Atomics waits. Owner probing on contention is bounded by the remaining wait. `recover-lock` requires a provably gone owner and uses a separate recovery guard. Unreadable locks or interrupted guards still require inspection. There are no standing loops, waiter services, age-based steals or background scans.

## Lifecycle and release contract

Slots move through `free`, `preparing`, `running`, `awaiting-review`, `releasing`, and `quarantined`. A preparation records its CLI process as preparer. A live or unknown preparer stays busy; only a gone preparer quarantines interrupted work. Only lease, resume, recover and status reconcile owners. Unknown observations never mutate a lane. Status uses boot and signal-zero existence checks without PowerShell; a present external PID remains unknown until a creation-time check. Allocation/recovery batch the necessary external owners into one Get-Process call. Capability-checked mutations perform no owner sweep. A sealed awaiting-review lane survives owner exit and can be released normally.

New lanes use a resolved base SHA and a newly created branch. Existing branch names and lane ids are refused. Verify lanes stay detached. Release requires the coordinator's explicit final SHA, clean tracked/index/untracked state, no unfinished Git operation, and a matching branch. It seals `refs/lanes/<lane-id>/final`, records base and final SHA, and detaches before publishing free. It never commits anything. Ignored output is covered by the declared cleanup policy: everything outside the allowlist is discarded only on the next preparation.

`checkpoint` seals a clean current commit for review without releasing. It can also seal a quarantined lane after the coordinator has repaired it. `recover` needs a provably gone owner, clean slot, no operation in progress, and an already recorded matching durable final ref. Dirty and unsealed slots remain quarantined, with the refusal reason recorded. A dead owner is not evidence that descendants stopped: the v1 coordinator must establish quiescence before checkpoint/release/recovery. The core never kills a process.

Resume acquires only the original slot, restores the recorded final tip and renews token/generation. A busy original slot refuses even if another slot is free. A moved branch is refused instead of reset. A deleted branch can be recreated from the durable final ref. An active or quarantined lane cannot be resumed as a second writer. Resolve, review/recover if needed, then resume using the recorded lane capability.

## Preparation and environment

Registration requires an existing pool root. Windows queries CIM once at registration for NTFS/serial and checks it against Node's dev value. Later checks compare realpath, dev and ino without a subprocess. A missing/replaced root has no fallback. Slot directories are lazy-created locked worktrees. Add, hard reset and switch get 30-minute deadlines. If first worktree add fails, only its proven-absent-beforehand path is rolled back: unlock/remove any registration, remove leftover files without following links, then prune. Successful rollback frees the slot and records a failed lane; use a new lane id for another lease. Other preparation failures preserve the slot in quarantine. Established pool slots are never retired by this path.

Git runs with inherited `GIT_*` routing variables removed, hooks disabled per invocation, and fsmonitor disabled. The core checks worktree registration and common metadata before mutation. It refuses submodules, nested repositories, sparse checkouts, unfinished operations, and content that uses Git filters. It clears assume-unchanged and skip-worktree flags before checking cleanliness. A free slot must be detached before reset, so preparation cannot reset a deliverable branch.

Cleanup enumerates with lstat and never walks a junction or symlink. It preserves only explicitly allowlisted generated directories. An environment link leaving the slot is refused. Main-checkout environments must never be junctioned into a slot. Environment fingerprints cover tracked dependency manifests/lockfiles, Node/runtime/ABI/platform and caller-supplied runtime versions/options. Every adapter must supply its package manager and other runtime/install option strings through `--runtimes`.

`env-begin` invalidates the previous install receipt; `env-ready` accepts the current fingerprint after a matching begin. This is the adapter's installation attestation, not package-content verification. Missing/mismatched receipts return `environment.stale: true`. Full environment link scans run during prepare, release and recover. Checkpoint still requires clean-tree state. Environment receipts validate the slot and fingerprint manifests on disk, including uncommitted manifest edits, without checking Git operations, clearing flags or writing the index. Untracked work does not block a reinstall. Download caches may be shared externally; installed environments may not.

## Lessons and adapter obligations

Git for Windows registers LFS filters globally even in an ordinary synthetic repository. Rejecting filter configuration rejects every such repository. Check attributes on the pinned target and current tracked content instead; refuse actual filter use before checkout/status can execute it.

Inspect hidden flags once during preparation or clean-tree verification; environment receipts never clear them. When present, clear assume-unchanged and skip-worktree separately: Git accepts both switches together but leaves one flag set. A common-directory match alone does not prove index isolation; require a regular slot gitfile, a linked-worktree admin directory and its reciprocal gitdir backpointer before mutation. Slow or failed identity probes are uncertainty, never proof of owner loss. Node uptime starts after OS creation and DLL loading, so an absolute creation-time difference can falsely declare a live holder gone. Apply the asymmetric self-start bound before lock recovery or reconciliation. Never hold a machine-wide state lock during checkout.

`--owner-pid` is mandatory for write, verify and integration leases and every resume. Only inspect/live leases can default to the parent PID. Never release on launcher exit. A worker may checkpoint and exit; the coordinator then reviews, accounts for evidence and descendants, and explicitly releases. This core neither writes evidence into the canonical tree nor verifies report content, review approval or descendant quiescence.

Keep one shared state directory for the machine-wide cap. Separate `HARBOR_LANES_DIR` values intentionally define separate isolated pools and cannot enforce a shared cap. Quarantined write slots conservatively continue to consume write capacity. Integration counts as a write lane. Verify lanes consume ordinary slots but not the write cap. Adapters still own their broader test/resource budget and legacy-worker accounting.
