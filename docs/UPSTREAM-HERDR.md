# Herdr, the daemon Harbor drives

Harbor is a GUI on a stock **Herdr 0.7.4** daemon. It never forks, patches or
embeds Herdr; it drives Herdr's documented third-party client surface, which is
a NDJSON unix socket plus the `herdr terminal session observe|control` byte
bridge, and it spawns the `herdr` binary as a separate process.

Upstream: <https://github.com/ogulcancelik/herdr>

## Why the docs are not mirrored here

This repository used to carry a verbatim copy of Herdr's documentation under
`docs/UPSTREAM-HERDR.md`, including several `.rs` source files. **Herdr is
dual-licensed AGPL-3.0-or-later or commercial.** Harbor is MIT, so shipping that
copy inside this tree would have redistributed AGPL material under an MIT notice.
The mirror is gone; read the upstream docs at the link above.

Pinned-version references in this repo (`SUPPORTED_PROTOCOLS`, the readiness and
recovery behaviour in `bin/herdr-server-clean`) name the upstream documents they
came from, so they are still followable.

## Why Harbor is MIT rather than AGPL

Harbor and Herdr are separate programs. Harbor does not link Herdr as a library,
does not include its source, and communicates with it only at arm's length over a
socket and by spawning its CLI, which is the ordinary
separate-programs-that-talk-to-each-other case rather than a derivative work.

That is a considered position and not legal advice. Anyone redistributing a
bundle that ships the Herdr binary alongside Harbor is doing something different
from what this repository does, and should read the AGPL and the upstream
commercial-licensing note first.

## The API schema

`docs/herdr-api.schema.json` is retained. It is the output of running
`herdr api schema --json` against an installed daemon: a factual description of
the wire interface Harbor validates itself against, generated by this project
rather than copied from upstream.
