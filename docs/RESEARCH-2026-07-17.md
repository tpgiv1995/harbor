## 3. Herdr upstream (decision-grade)

- Fully open source: Rust, ~245 .rs files (~200k lines), AGPL-3.0-or-later OR commercial,
  github.com/ogulcancelik/herdr, 17,285 stars, weekly stable releases (0.7.4 on
  2026-07-15), sole full-time maintainer, community PRs accepted.
- Local: herdr 0.7.4, protocol 16, socket /home/you/.config/herdr/herdr.sock.
  Named sessions get their own socket under /home/you/.config/herdr/sessions/.
- Public socket API: 85 methods, newline-delimited JSON over the unix socket. Ground-truth
  schema dump: /home/you/dev/harbor/docs/herdr-api.schema.json
  (regenerated 2026-07-17 via `herdr api schema`, protocol 16, schema_version 1).
- THIRD-PARTY FRONTENDS ARE AN INTENDED USE CASE. Upstream AGENTS.md: "Herdr is migrating
  toward a server-owned runtime protocol with the TUI as one client." v0.7.2 shipped
  `session.snapshot` (full state bootstrap), `layout.updated` events, and the terminal
  bridge: `herdr terminal session observe <pane>` (NDJSON terminal.frame records, base64
  ANSI bytes, multi-observer) and `herdr terminal session control <pane> [--takeover]`
  (adds terminal.input/resize/scroll/release; ONE controller owns input at a time).
  Documented "For third-party bridges that only need rendered terminal bytes"
  (`persistence-remote.mdx` lines 133-155, in Herdr's own upstream docs, mirrored locally
  at research time; that local mirror was later removed, see `docs/UPSTREAM-HERDR.md`).
  Verified present in the installed 0.7.4 binary.
- events.subscribe: 26 event types (workspace/tab/pane lifecycle, pane.agent_status_changed,
  pane_output_changed revision pushes, layout.updated). KNOWN BUG upstream issue #1270:
  new subscribers get replayed historical events; bootstrap with session.snapshot and
  dedupe by ids/revisions.
- Stock TUI sidebar ceiling confirmed: metadata token rows are text-only, no per-row click
  actions, plugin v1 has no native UI. A clickable-sessions sidebar is NOT reachable inside
  the TUI without forking. The GUI head removes this ceiling entirely.
- Verdict: drive the stock daemon (LOW-MODERATE cost). Fork = HIGH (permanent rebase tax
  against a weekly-release 200k-line codebase). Replace = VERY HIGH (reimplement PTY mux,
  restore, agent detection, layout, plugins). Pin 0.7.4: archive the binary, `herdr update`
  is manual-only (never call from automation), assert protocol 16 + schema_version 1 on
  connect. Upstream small PRs where the API falls short.

## 4. Orchestration stack contracts

- /home/you/.local/bin/claude-delegate: 1,725-line stdlib Python. Queues at
  /home/you/.local/state/claude-delegate/queues/<sha1(cwd)[:12]>.json, named workers
  at /home/you/.local/state/claude-delegate/workers.json. Scoping is PURE CWD:
  spawn every delegate process with cwd = the project root or you operate a phantom queue
  (4 of 6 existing queue files are phantom scratchpad-keyed ones).
- Batch statuses: pending -> active (dispatched) -> done | blocked | error, judged and
  transitioned by the ORCHESTRATOR (queue done / queue blocked), not the worker.
- Workers are synchronous print-mode CLI runs spawned by the delegate:
  claude: `claude -p --output-format json --permission-mode bypassPermissions --add-dir <ws>`
  with CLAUDE_CONFIG_DIR from CLAUDE_DELEGATE_CLAUDE_CONFIG_DIR (env.sh pins workers to
  the PERSONAL home; the interactive orchestrator seat is TEAM). Lanes by name prefix:
  sonnet-* / opus-* (xhigh) / haiku-*.
  codex: exec --json, dual homes with usage-limit failover. cursor: agent --print,
  composer-2.5 default.
- FleetView is NOT a local tool: it was Claude Code's own background-agents board in the
  Windows desktop app (tengu_fleet_* flags). Its role here is filled by herdr + harbor.
- Headless kickoff proven: `claude -p "/orchestrate-research <goal>"` resolves skills.
  Watchable kickoff: run it interactively inside a herdr pane instead (this is what the
  GUI should do). Poll by reading the queue JSON directly. Never run two executions
  against the same workspace (whole-file tmp+rename, no locking).
