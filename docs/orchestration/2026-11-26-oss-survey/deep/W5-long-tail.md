## 1. The ten most useful new ideas (ranked)

None repeats REPORT.md's top ten. Where an idea touches one of them, I say how.

### 1. Workspace facts on every rail row and window header: branch, changes, PR, ports (small for git, medium for ports)
- **Seen in:** [cmux](https://github.com/manaflow-ai/cmux) (28,978 stars, R): its sidebar shows "git branch, linked PR status/number, working directory, listening ports, and latest notification text" per tab. [abtop](https://github.com/graykode/abtop) (3,884, Windows native, R): "Agent spawned a server and forgot to kill it? Orphan port detection", plus child processes per session. [Calyx](https://github.com/yuuichieguchi/Calyx) (367, R): Mission Map cards carry branch and token use. [supacode](https://github.com/supabitapp/supacode) (2,399, R) tracks each worktree's PR state and checks. [claude-control](https://github.com/sverrirsig/claude-control) (139, list) shows git changes and PR checks per session.
- **Harbor today:** none of it (section 0).
- **Fit:** the rail already knows each session's `cwd`. Branch and dirty count come from one `git status --porcelain=v2 -b` per folder, refreshed when that session's transcript changes, never on a timer (the doctrine in `docs/claude/performance.md`). Use `execFile` with `windowsHide: true`, as `data-status.js:73` does. Listening ports per session need the session's process tree (`main/session-daemon/process-tree.js` exists) joined to the TCP table. abtop uses `netstat -ano`, but Harbor's own memory note says process questions cost 3 to 5 seconds through CIM, so read the TCP table through `koffi` in the daemon. PR and check state is a `gh` call per branch, cached, and optional.
- **Why first:** it answers "which window is that, and is its dev server still up".

### 2. Warn when two live sessions share one working tree (small for the badge, medium for file overlap)
- **Seen in:** [claude-bulkhead](https://github.com/dooly6276/claude-bulkhead) (35 stars, pushed 2026-11-23, Windows, R). Its guards block `git add -A`, `git commit -a`, `checkout`, `reset --hard`, `clean -f` and `git worktree remove` when another live session works in the same tree, block `pkill node` and kill-by-port against other sessions' servers, and queue heavy jobs by free RAM. Same theme in [concord-mcp](https://github.com/Get-Concord-AI/concord-mcp) (1,579, R: "file-claim overlap detection before edits"), [foremerge](https://github.com/naw103/foremerge) (408, R: agents publish intent and scope, rules flag colliding plans), [hcom](https://github.com/aannoo/hcom) (677, R: subscribe to "collisions"), [ntm](https://github.com/Dicklesworthstone/ntm) (466, R: file reservations) and [kander](https://github.com/dualface/kander) (338, R: conflict-aware scheduling).
- **Harbor today:** nothing flags it, and it is a known pain: Harbor's own `CLAUDE.md` records a parallel session sweeping 18 staged files into an unrelated commit on 2026-11-06.
- **Fit:** group live sessions by the git top-level of their `cwd` (the same call as idea 1). Two or more live sessions in one tree get a badge on each row naming the others. Step two uses data Harbor already parses: the Edit and Write records in each transcript give the files each session touched, so the badge can say "both touched `app/src/main/index.js`". Do not copy bulkhead's blocking hooks into Harbor; show the fact and let the person or the project's own hooks act.

### 3. Link sessions and commits, and recover a clobbered edit from the transcript (small for the link, medium for restore)
- **Seen in:** [deja-vu](https://github.com/vshulcz/deja-vu) (1,677, pushed 2026-11-26, R): `deja restore <path>` recovers an uncommitted edit span an agent replaced, from the recorded `old_string`; `deja blame` and `deja origin` map commits and lines back to the session that wrote them. [shift-log](https://github.com/re-cinq/shift-log) (53, last push 2026-09-12, R) attaches the conversation since the last commit to the commit as a git note, so `shiftlog resume <sha>` reopens it. [Entire](https://github.com/entireio/cli) (5,354, R) records each session as a checkpoint linked to its commits. [agentdiff](https://github.com/codeprakhar25/agentdiff) (48, R) signs per-line attribution; I would not take that part.
- **Harbor today:** no commit parsing and no restore. REPORT.md section 3 covers rewind and fork, which undo a turn. This is different: find which session made a commit, and get back an edit another session overwrote.
- **Fit:** a Bash tool result that shows `[branch abc1234] message` is already in the transcript. Harbor can list "commits made by this session" in the window header and let a pasted SHA open its session in rail search. The restore half re-reads the session's Edit records (old and new string, path, order) and offers the last replaced span for a file. It leans on the same problem as idea 2.

### 4. A "what is sent every turn" panel: skills that arrive as bare names, MCP tool weight, instruction files (medium)
- **Seen in:** [context-tax](https://github.com/gethrbr/context-tax) (6 stars, pushed 2026-11-10, R) reads the session transcript's record of what Claude Code put in the prompt. Its first finding is "what your agent never received": past a budget of 1% of the context window in characters, Claude Code sends a skill as a bare name with no description, so an installed skill can be invisible in every session. [claude-devtools](https://github.com/matt1398/claude-devtools) (4,057, R) attributes each turn's tokens to seven categories (CLAUDE.md, skills, @-mentioned files, tool input and output, thinking, team overhead, user text) and draws compactions. [skillreaper](https://github.com/thousandflowers/skillreaper) (68, R) finds skills, MCP servers and agents loaded but never fired (its own run: 382 loaded, 13 fired).
- **Harbor today:** nothing. The `api-request` records are skipped for speed (`transcript.js:2244`). The context gauge in `renderer/stage/CommandBar.jsx:677` shows one percent.
- **Fit:** this is Pat's own recorded problem (memory entries "Skill listing budget + CRLF frontmatter" with `SLASH_COMMAND_TOOL_CHAR_BUDGET`, and "Plan usage economics: 74k MCP floor"). A chip beside the context gauge that opens a short table (skills sent as bare names, largest MCP servers, instruction files by size, growth per turn) would show it per session without a separate tool. Read once per session from the first `api-request` record, not every turn, to respect the whole-file-read rule. This extends REPORT.md section 6's "waste findings" from cost to correctness.

### 5. Continue on another CLI or plan when one runs dry (medium)
- **Seen in:** [agent-bridge](https://github.com/raysonmeng/agent-bridge) (439, R): "Quota relay for overnight runs: when one side's subscription window runs dry, it stops cleanly at a turn boundary and hands the task off to the other side". [sno-station](https://github.com/sno-ai/sno-station) (1,028, R): "One agent runs low. A different one continues from the same commit." [deja-vu](https://github.com/vshulcz/deja-vu) `deja handoff` transfers goal, constraints, touched files and passed checks across agents. [pond](https://github.com/tenequm/pond) (93, R) restores any session into any supported client. [claudexor](https://github.com/razzant/claudexor) (528, R) keeps one thread across Claude, Codex, Cursor and OpenCode.
- **Harbor today:** move-session-to-plan stays inside Claude (one provider, 15 homes); the handoff chain stays inside one session.
- **Fit:** write the handoff file Harbor already knows how to ask for, add facts it can read (touched files from Edit and Write records, last test result, branch), and start a Codex, Cursor or agy session in the same folder with it as the first message. It pairs with REPORT.md item 5 (Harbor already knows every account's reset time). The risk is quality: the second CLI starts without the first one's context, so the handoff text has to carry the decisions.

### 6. Resend after a transient API error, and show provider incidents (small)
- **Seen in:** [Maestro](https://github.com/RunMaestro/Maestro) (3,630, R) "Agent Resilience": "When a turn dies on `529 Overloaded` or a spent plan quota, Maestro resends the exact prompt on its own, backing off in seconds for a blip or waiting for the real reset time it reads out of the error. One live status card replaces the wall of error dialogs." [wmux](https://github.com/openwong2kim/wmux) (465, R) pauses a limited pane and holds scheduled prompts and agent messages for it instead of typing them into a turn that cannot run. [CodexBar](https://github.com/steipete/CodexBar) (23,350, R) polls provider status and draws an incident badge.
- **Harbor today:** an API-error turn counts as `idle` (`claude-turn-state.cjs:9`); nothing resends, and nothing says the provider is down.
- **Fit:** REPORT.md item 5 covers the usage-limit case. This adds the transient case: read the error row, back off, resend once or twice, then stop and show one card. A provider incident badge (a read of each provider's public status page, only while a session is blocked) would also explain a stalled window. Two cautions: resend only the last user prompt and only when no tool ran after it, and never resend into a window that shows a permission or question dialog.

### 7. Flag sessions stuck in a fix-and-retry loop (small to medium)
- **Seen in:** [MartinLoop](https://github.com/Keesan12/martin-loop) (262, R): `martin-loop audit` reads Claude Code session history locally and reports "how much API-equivalent agent spend happened inside fix-and-retry loops, how often verifier commands failed, the longest retry chain, and sessions that ended red"; its governed runs add a budget, an iteration cap and stop conditions. [clawmetry](https://github.com/vivekchand/clawmetry) (440, R) shows "trajectory signals (looping, repeated failures)". [coworkers](https://github.com/fayazara/coworkers) (478, R) has "a loop guard [that] stops the bot from repeating the same call over and over".
- **Harbor today:** nothing detects repetition.
- **Fit:** from the transcript, count the same command (or the same edit to the same file) failing N times in a row and put a small "looping x6" mark on the rail row, with the tokens spent inside the loop. It is cheap and catches the sessions that quietly burn a plan. It complements REPORT.md section 9's wall-clock cap for workers.

### 8. Start clear-and-resume automatically at a context threshold (small to medium)
- **Seen in:** [aigent-os](https://github.com/wrg32786/aigent-os) (26 stars, pushed 2026-11-24, R): at a set context level (default 80%) it asks the agent for a capsule, sends `/clear`, and the fresh session resumes from the capsule. Its README shows 11 of 11 cycles on one Windows seat and states a known limit: on rc.1 a long session can stop at the clear step. [Continuous-Claude-v3](https://github.com/parcadei/Continuous-Claude-v3) (3,954, R) says "compound, don't compact", with handoff files and hooks.
- **Harbor today:** the manual chain `handoff-chain.cjs` already does `/handoff`, `/compact`, `/pickup` and proves each step from the transcript, and the context percent is on screen. What is missing is the trigger.
- **Fit:** an opt-in per-window toggle, "hand off at 85%", that starts the existing chain when the turn ends. Off by default; never started in a window waiting on a question or permission. Harbor's chain fails with a stated reason, which is safer than aigent-os's rc.1 stall.

### 9. Each session's share of the plan window (small to medium)
- **Seen in:** [Agent Sessions](https://github.com/jazzyalex/agent-sessions) (954, macOS, R): "See which session is burning your quota. Track live per-session Codex and Claude burn against 5-hour and weekly windows." [Claude Code Agent Monitor](https://github.com/hoangsonww/Claude-Code-Agent-Monitor) (1,215, R) and [agentacct](https://github.com/mikehasa/agentacct) (758, R; labels every usage-to-work join with a confidence level) attribute tokens to sessions.
- **Harbor today:** plan meters show the account, and move-session-to-plan is manual. Which session is draining the account is not on screen.
- **Fit:** the usage block per assistant record is already parsed for the context gauge. Summing it per session over the meter's own window and showing "this session: 31% of the window" on the rail row makes the move-or-stop decision a glance. It overlaps REPORT.md item 6 (cost per session) but answers a different question: share of the limit, not dollars.

### 10. Edit or erase one message in a closed session, then resume (medium, lowest confidence)
- **Seen in:** [Memory Forge](https://github.com/voidcraft-dev/memory-forge-rs) (519, pushed 2026-11-22, R): "Edit any message in AI conversation history, then seamlessly continue", rewriting only the changed line, keeping a backup before each edit and an audit log with before and after. It covers Claude Code, Codex and about 18 other tools.
- **Harbor today:** Harbor never writes a session file. REPORT.md section 3 covers rewind and fork; neither removes a wrong assumption from the middle of a long conversation.
- **Fit:** only for sessions with no live process; back up first; refuse when the CLI's record format is unknown. Cost: every turn after the edit is processed again once (the prompt cache restarts). I rank it last because the CLIs' record formats change often and a bad rewrite loses a session, while ideas 1 to 9 only read.
