## Where it lives

Harbor is the home (it already owns orchestration actions, the delegate reader and the `bin\` organs; launchers outside Harbor will call this CLI):
- CLI: `bin\harbor-lane` (same shape as the other `bin\` organs: a thin script that requires a `.cjs` module; read `bin\harbor-lean` and `bin\harbor-board` for the pattern). Subcommands at minimum: `init-repo` (register a repo id, canonical path, pool size, allowlist), `lease` (new lane: repo, lane id, branch name, base SHA or ref resolved to a SHA, lane type), `resume` (lane id: restore the recorded branch tip into its original slot), `status` (pool and lanes, JSON), `release` (lane id: checks, durable ref `refs/lanes/<lane-id>/final`, detach, slot to free), `recover` (slot: re-check a quarantined slot), `quarantine` (explicit). Every command prints one JSON object; exit codes documented.
- Module: `app\src\shared\lane\*.cjs` (plain Node, no Electron, no new dependencies).
- State OUTSIDE the pool: `~/.harbor/lanes/` on real installs (registry plus an append-only journal), overridable by `HARBOR_LANES_DIR`. Tests MUST set `HARBOR_LANES_DIR` and a temp pool root; nothing in this round may create or touch `~/.harbor/lanes` or `C:\dev\.orch\pool`.
- Concurrency: one repository-level lock (an exclusive-create lock file with owner identity, journaled, recovered by the same owner checks; never by age), held across claim, prepare and publish.
- Tests: `app\test\lane\*.test.js` (Node built-in test runner, run with `npm test -- lane` from `app\`). Use real temporary git repositories built by the test (synthetic content only: the repo is published publicly; no real names, clients or paths of other projects in fixtures).

## Proofs required (each as a test that fails without the behavior)

New lane refuses an existing branch or lane id; resume restores the recorded tip and never resets to base; release preserves the final commit under the durable ref and detaches; a dirty slot cannot be released and becomes quarantined on owner loss; an interrupted prepare (simulate a failure mid-sequence) leaves the slot unavailable, not free; two concurrent lease calls never get the same slot (spawn real child processes racing); hidden index flags from a previous lane do not leak; a junction inside a slot is not followed by the clean; an allowlisted dependency folder survives reuse while a non-allowlisted ignored file does not; dependency fingerprint mismatch is reported; POOL_FULL when full; the integration slot is never handed to a write lane; a stale token (old generation) cannot release or change the newer occupant; Windows: a file held open in the slot makes reset fail safely (slot unavailable, reason recorded).
